# Nova — локальный голосовой AI-ассистент

**Nova** — локальный голосовой AI-ассистент на Python с использованием Whisper, локальной LLM через `llama.cpp` и локального синтеза речи.

Проект развивается как модульная система, в которой распознавание речи, анализ запроса, выполнение команд, работа с памятью и формирование ответа разделены между отдельными компонентами.

Название **Nova** отсылает к астрономическому термину *nova* — вспышке звезды. Для проекта это символ новой точки отсчёта: ассистента, который постепенно учится понимать пользователя, запоминать его историю и становиться персональным помощником.

> **Nova — новая звезда, которая постепенно становится персональным ИИ-помощником пользователя.**

---

## Возможности

На текущем этапе Nova умеет:

* распознавать голос пользователя через Whisper;
* обрабатывать естественный язык с помощью LLM;
* определять намерение пользователя;
* формировать структурированные команды;
* выполнять команды через отдельные обработчики;
* работать с внешними API;
* сохранять информацию о пользователе;
* хранить долговременную память в SQLite;
* запоминать информацию о связанных с пользователем людях;
* формировать естественные ответы;
* озвучивать ответы через локальный TTS;
* работать с локальной LLM через `llama.cpp`;
* переключаться между локальной и облачной моделью через конфигурацию.

Проект находится в активной разработке.

# Архитектура

Основной принцип Nova — разделение ответственности между компонентами.

```text
                    ┌───────────────┐
                    │    Whisper    │
                    └───────┬───────┘
                            ↓
                          текст
                            ↓
                    ┌───────────────┐
                    │    Butler     │
                    │               │
                    │ command       │
                    │ parameters    │
                    │ memory        │
                    │ prompt        │
                    └───┬───────┬───┘
                        ↓       ↓
                    Command    Memory
                    Handler    Manager
                        ↓       ↓
                       API     SQLite
                        └───┬───┘
                            ↓
                    ┌───────────────┐
                    │   Responder   │
                    └───────┬───────┘
                            ↓
                          Nova
```

### Основной поток

```text
Микрофон
   ↓
Whisper
   ↓
текст пользователя
   ↓
Butler
   ↓
┌──────────────────────┐
│ command              │
│ parameters           │
│ memory               │
│ prompt               │
└──────────────────────┘
   ↓              ↓
Handler       Memory Manager
   ↓              ↓
 API            SQLite
   └───────┬──────┘
           ↓
       Responder
           ↓
      готовый ответ
           ↓
          TTS
           ↓
       голос Nova
```

# Компоненты

## Whisper

Whisper отвечает за распознавание речи пользователя.

```text
Голос → Whisper → текст
```

Распознавание выполняется локально, без необходимости отправлять аудиозапись во внешний сервис.

---

## Butler

**Butler** — компонент, отвечающий за анализ пользовательского запроса и принятие решения о дальнейших действиях.

Он определяет:

* какую команду необходимо выполнить;
* какие параметры нужны команде;
* нужно ли изменить долговременную память;
* какой prompt необходимо передать для формирования ответа.

Например:

```text
Пользователь:

Какая сейчас погода в Батуми?
```

Butler преобразует запрос в структурированные данные:

```json
{
    "command": "weather",
    "parameters": {
        "city": "Батуми"
    },
    "memory": {
        "action": "ignore"
    },
    "result": null,
    "prompt": "Получи информацию о погоде в Батуми и сообщи пользователю."
}
```

Butler не выполняет команды самостоятельно.

---

## Command Handler

`Command Handler` отвечает за выполнение команды, которую определил Butler.

Например:

```text
Butler
   ↓
command = weather
   ↓
Command Handler
   ↓
Weather API
   ↓
результат
```

Такой подход позволяет добавлять новые команды и инструменты без изменения основной логики Nova.

---

## Memory Manager

`Memory Manager` отвечает за долговременную память пользователя.

На текущем этапе для хранения данных используется SQLite.

Память предназначена для информации, которую Nova должна сохранять между запусками программы.

Например:

```text
Имя пользователя
Любимая игра
Хобби
Текущая игра
Члены семьи
Отношения между людьми
Дополнительные факты
```

Butler принимает решение о необходимости изменения памяти, а Memory Manager выполняет соответствующую операцию.

---

## Responder

Responder отвечает за формирование финального ответа пользователю.

Он получает:

* команду;
* параметры;
* результат выполнения команды;
* доступный контекст;
* информацию из памяти, если она релевантна.

После этого формирует естественный ответ.

Например:

```text
Weather API
     ↓
+18°C, дождь
     ↓
Responder
     ↓
"Сейчас в Батуми 18 градусов и идёт дождь."
```

Responder не выполняет команды и не обращается к API напрямую.

---

## Text-to-Speech

После формирования ответа текст передаётся в локальную систему синтеза речи.

```text
Responder
   ↓
текст
   ↓
TTS
   ↓
голос Nova
```

# Локальная LLM

Nova использует локальную языковую модель через `llama.cpp`.

Текущая модель:

```text
Qwen3-8B-Q4_K_M.gguf
```

Для ускорения инференса модель запускается через Vulkan и использует GPU.

## Текущая конфигурация

Проект тестируется на следующем оборудовании:

```text
GPU:  AMD Radeon RX 590 8 GB
CPU:  AMD Ryzen 7 2700
RAM:  16 GB
OS:   Windows
```

Для работы локальной модели требуется сборка `llama.cpp` с поддержкой Vulkan.

# Запуск llama-server

Перейдите в каталог с `llama.cpp`:

```powershell
cd D:\AI
```

Запустите сервер:

```powershell
.\llama-server.exe `
    -m "D:\AI\models\Qwen3-8B-Q4_K_M.gguf" `
    -ngl 99 `
    -c 4096 `
    -t 12 `
    --port 8080 `
    --reasoning off
```

После запуска локальная модель будет доступна через OpenAI-compatible API:

```text
http://127.0.0.1:8080/v1
```

Nova обращается к локальной модели через этот API.

# Локальная и облачная модели

Архитектура Nova позволяет переключать провайдера модели через конфигурацию.

### Локальная модель

```text
Nova
  ↓
llama.cpp
  ↓
Qwen3
```

### Облачная модель

```text
Nova
  ↓
OpenRouter
  ↓
выбранная модель
```

Остальная архитектура приложения не должна зависеть от конкретного провайдера.

Это позволяет менять модель без переписывания основной логики Nova.

# Принципы проекта

## Разделение ответственности

Каждый компонент отвечает за свою область:

```text
Whisper        → распознавание речи
Butler         → принятие решений
Command Handler → выполнение команд
Memory Manager → долговременная память
Responder      → формирование ответа
TTS            → озвучивание
```

## Независимость компонентов

Основная логика Nova не должна зависеть от конкретного API, сервиса или модели.

## Структурированный обмен данными

Butler использует строгую структуру команд.

Это позволяет отделить:

```text
принятие решения
```

от:

```text
выполнения действия
```

## Расширяемость

Новые возможности должны добавляться как отдельные инструменты или команды.

Например:

```text
weather
music
telegram
calendar
smart_home
search
```

без необходимости переписывать ядро приложения.

# Система памяти

Одно из основных направлений развития Nova — полноценная долговременная память.

Планируемая система будет разделена на несколько логических уровней:

```text
                    Memory System
                         │
          ┌──────────────┼──────────────┐
          ↓              ↓              ↓
       Profile        Relations       Facts
          │              │              │
          └──────────────┼──────────────┘
                         ↓
                  Context Manager
                         ↓
                       Butler
```

Память должна хранить не только информацию о самом пользователе, но и связанные сущности.

Например:

```text
Андрей
 ├── жена ────────→ Карина
 ├── дочь ────────→ София
 └── друг ────────→ Кирилл
```

У связанных людей также могут существовать собственные факты:

```text
София
 └── любимая еда → бананы
```

В дальнейшем Context Manager должен выбирать из памяти только информацию, которая относится к текущему запросу.

Например:

```text
"А какую еду любит моя дочь?"
                ↓
             Context
                ↓
             София
                ↓
          favorite_food
                ↓
             бананы
```

Nova не должна передавать LLM всю базу данных при каждом запросе.

# План развития

Основная цель проекта — постепенно превратить Nova из простого голосового интерфейса в полноценного персонального локального ассистента.

Планируемые направления:

```text
                    Nova
                     │
        ┌────────────┼────────────┐
        ↓            ↓            ↓
     Memory        APIs          AI
        │            │            │
        ↓            ↓            ↓
    Context       Music       Local LLM
    Manager      Telegram     Cloud LLM
        │         Weather
        │         Calendar
        ↓
   Personal Context
```

Планируемые возможности:

* долговременная память;
* контекст последних сообщений;
* история диалога;
* автоматическое создание сводки длинных разговоров;
* семейное и социальное графовое представление;
* музыкальный API;
* Telegram API;
* дополнительные внешние API;
* улучшенная работа с многоязычным текстом;
* более естественный голосовой диалог;
* расширение набора локальных инструментов.
