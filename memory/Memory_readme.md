# Memory System — Nova

Документ описывает текущее состояние памяти Nova, целевую архитектуру и план её развития.

---

## 1. Что есть сейчас

Nova уже имеет базовую **Long-Term Memory**.

Хранятся:

- профиль пользователя;
- факты о пользователе;
- связанные люди;
- отношения между пользователем и людьми;
- факты о связанных людях.

Основные сущности:

```text
User
UserFact
RelatedPerson
Relation
PersonFact
```

Контекст собирает Context Manager и передаёт его в Butler.

Текущая схема:
```code
Profile
Facts
Relations
People
   ↓
Context Manager
   ↓
Butler
```

Пока отсутствует
- история сообщений;
- Short-Term Memory;
- последние 10 сообщений;
- история последних 100 сообщений;
- Conversation Summary;
- поиск по старым разговорам;
- embeddings;
- semantic search;
- автоматическая консолидация памяти.


## 2. К чему хотим прийти

Nova должна не только хранить факты, но и уметь вспоминать предыдущие разговоры.

Целевая архитектура:


## 3. Три уровня памяти
Long-Term Memory

Постоянная информация:

```code
Кто пользователь
Семья
Работа
Предпочтения
Важные факты
Short-Term Memory
```

Непосредственный контекст:

```code
Последние 10 сообщений
```

Используется для продолжения текущего разговора.

Experience Memory

Память предыдущих разговоров:

```code
100 сообщений
      ↓
   Summary
      ↓
Experience Memory
```

Summary содержит:

- основные темы;
- важные события;
- принятые решения;
- открытые вопросы;
- период разговора;
- ссылки на исходные сообщения.


## 4. Как искать старые разговоры

Поиск должен работать по уровням:

```code
Текущий запрос
      ↓
Последние 10 сообщений
      ↓
Если недостаточно
      ↓
Поиск по summaries
      ↓
Если недостаточно
      ↓
Поиск оригинальных сообщений
```

В дальнейшем поиск должен стать семантическим:

```code
Запрос
  ↓
Embedding
  ↓
Vector Search
  ↓
Relevant Summaries
```

При этом SQLite остаётся источником истины, а векторный индекс используется только для поиска.

## 5. Консолидация памяти

Nova должна периодически "систематизировать опыт".

На первом этапе:

```code
Запуск Nova
    ↓
100 сообщений
    ↓
Summary
```

Позже:

```code
100 сообщений
      ↓
Conversation Summary
      ↓
Daily Summary
      ↓
Weekly Summary
```

Исходные сообщения никогда не удаляются.

Summary — это производный слой памяти.

## 6. План развития
Этап 1 — Conversation History

Создать хранение всех сообщений:

ConversationMessage
Этап 2 — Short-Term Memory

Добавить получение последних 10 сообщений.

Этап 3 — Conversation Buffer

Использовать последние 100 сообщений как материал для консолидации.

Этап 4 — Conversation Summary

Создать ConversationSummary.

```code
100 сообщений
      ↓
LLM
      ↓
Summary
```

Этап 5 — Поиск summaries

Сначала:
```code
keywords
topics
date
```

Этап 6 — Semantic Search

Добавить embeddings и vector search.

Этап 7 — Deep Retrieval

Если summary недостаточно — получать оригинальные сообщения.

Этап 8 — Автоматическая консолидация

Запускать создание summaries автоматически, например несколько раз в день.

Этап 9 — Улучшение Retrieval

Добавить:

```code
Keyword Search
+
Semantic Search
+
Recency
+
Importance
=
Final Ranking
```


## 7. Главные принципы
- Не удалять оригинальные сообщения.
- Summary не заменяет исходные данные.
- Не отправлять всю память в prompt.
- Context Manager выбирает только релевантную информацию.
- SQLite остаётся источником истины.
- Vector Search используется для поиска, а не как основная БД.
- Сначала простая реализация, затем embeddings и сложный retrieval.
- Каждый этап должен работать самостоятельно.


## 8. Конечная цель

```code
Nova знает пользователя
        +
понимает текущий разговор
        +
помнит предыдущие разговоры
        +
умеет находить нужные воспоминания
        +
умеет восстанавливать детали
        +
периодически систематизирует опыт
```

Главная цель Memory System: Nova должна не просто хранить информацию, а уметь вспоминать.
